- 2026-09-01 defer-evil
    - Problem: remove Evil's synchronous `require` from the measured startup path.
    - Tried methods: moved Evil loading, mode activation, and global Evil bindings into one idempotent initializer; schedule it on a zero-second idle timer, and call the same initializer before loading `chin-first-call.el` on the first-command path. Replaced the Evil macro calls in the deferred function with `evil-define-key*`, the function used by the macro expansion.
    - Decision / rejected alternatives: keep the deferred implementation. Twelve TTY launches measured 0.050–0.056 s total and 0.028–0.032 s init, down from 0.167–0.173 s. The unavoidable trade-off is a possible first-key race if input arrives before the idle callback; deterministic Evil semantics for the first key require eager loading.
