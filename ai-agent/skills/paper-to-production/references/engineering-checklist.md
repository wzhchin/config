# 工程化 Gap 分析框架

Step 4 的骨架。逐维度对照「论文方法」和「工业场景要求」，找出 Gap 和补法。

每个维度产出三段：**论文怎么说** / **场景要求什么** / **Gap + 补法**，并打标 🔴硬伤 🟡可工程化 🟢直接可用。

> 这是通用框架，不预设领域。ML 算法和系统类论文都能套——具体到某维度不适用时，标"本场景不涉及"即可，不要硬填。

---

## 维度 1: 功能契合度

- 论文方法解决的核心问题 = 用户场景的核心问题吗？
- 是直接命中，还是只是"看起来相关"？很多论文方法名头响，实际解决的子问题和用户痛点错位。
- 输入输出契约能否对上？论文要的输入，场景拿得到吗？论文的输出，场景消费得了吗？
- **典型 Gap**：论文解决的是离线全量问题，场景要的是在线增量；论文做排序，场景要的是召回。

## 维度 2: 性能与延迟

- 论文的推理/计算成本，在场景的延迟预算内吗？
- 区分训练时成本（一次性，可摊销）vs 推理时成本（每次请求都付）。
- 吞吐：论文的实验规模 vs 场景的 QPS，差几个数量级？
- **补法方向**：模型蒸馏 / 量化 / 剪枝 / 缓存 / 批处理 / 异步化 / 预计算 / 分级计算（粗排→精排）。
- **红线**：如果方法本质是 O(n²) 且 n 在场景里是百万级，可能直接 🔴。

## 维度 3: 数据

- 论文用的数据集 vs 场景的真实数据：分布、规模、质量差异多大？
- 标注：论文假设有标注，场景标注成本如何？能否弱监督/伪标签/主动学习？
- 分布漂移：论文是静态数据集，场景数据会随时间变化吗？变化速度多快？
- 数据可得性：特征/信号在场景里真的拿得到吗？合规/隐私约束（GDPR、数据出境）？
- **典型 Gap**：论文在干净公开数据上 work，场景数据脏/稀疏/有偏。

## 维度 4: 可靠性与降级

- 方法失败时（输入异常、模型超时、依赖宕机）会怎样？
- 场景能容忍多大的错误率？错误的代价多大？（推荐错了刷新一下；风控错了拒掉正常交易；医疗错了出人命）
- 能否降级到简单可靠的兜底策略？
- **典型 Gap**：论文只报告平均指标，但场景关心 worst case / 长尾。

## 维度 5: 成本

- 算力：训练一次多少钱？推理单次成本？是否需要专用硬件（GPU/大内存）？
- 人力：维护这个方法的团队成本，团队熟悉度。
- 对比基线：比现有的简单方法（规则、线性模型、已有方案）好多少？好出来的部分值这个成本吗？
- **红线**：成本是现有方案的 10 倍，效果只提升 2% → 通常不划算。

## 维度 6: 集成与部署

- 方法怎么嵌进现有系统？同步调用 / 异步队列 / 批处理管道？
- 能否引入新依赖（新框架、新服务、新基础设施）？环境约束（内网、无法联网拉模型、k8s/物理机）？
- 模型/方法的版本管理、回滚机制？
- **典型 Gap**：论文用 PyTorch + 实验环境，场景是 Java 后端 + 严格依赖管控。

## 维度 7: 可观测性与运维

- 怎么知道方法在线上"还在 work"？指标怎么埋点？
- 数据漂移 / 概念漂移怎么检测？检测到之后怎么触发重训？
- 能解释/审计吗（合规要求、用户投诉定位）？
- **典型 Gap**：论文是一次性实验，线上要持续监控 + 自动化重训闭环。

## 维度 8: 风险与不确定性

- 论文结论的稳健性：只在 1-2 个数据集上验证？消融实验充分吗？有没有被后续工作推翻？
- 方法的成熟度：是 5 年前的经典（工程化成熟）还是上个月的新论文（坑未知）？
- 有没有已知的失败模式（论文 limitation 章节或社区复现反馈）？
- **决策影响**：成熟度低 → 即使方向对，也建议先 PoC 而非直接全量。

---

## 输出优先级

分析完 8 维度后，**按 Gap 的严重程度排序**，而不是按维度顺序罗列。README 的核心结论里，只突出 🔴 硬伤 和 Top 3 🟡 改造项，其余进 gap-analysis.md 详情。

判断整体可行性的经验法则：
- 有任一 🔴 且无法消除 → ❌ 不建议落地
- 多个 🟡 但都有明确补法 → ⚠️ 有条件落地（PoC 先验证补法有效）
- 主要是 🟢 + 少量 🟡 → ✅ 建议落地
