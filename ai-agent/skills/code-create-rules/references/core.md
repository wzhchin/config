# Core Creation Rules

Before creating anything, determine whether the target belongs to an existing project.

For an existing project, follow its repository instructions and established conventions. Apply this skill only when the user explicitly requests it.

Follow the user's explicit requirements before these defaults.

Preserve unrelated working-tree changes.

Use the project's existing build, test, format, and package interfaces.

Limit changes to the requested scope.

When project work depends on a password, token, private key, certificate, keystore, or other secret, retrieve it with `kpass`.

Verify each change with the narrowest relevant check.

Report unverified behavior and environment limits.
