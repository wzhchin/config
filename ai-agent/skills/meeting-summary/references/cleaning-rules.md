# 转写文稿清洗与校对规范

本规范用于生成 `<prefix>-文字记录.md`，目标是让原始录音转写稿达到**“读起来像高质量人工整理稿，但信息保真度等同原始记录”**的标准。

## 1. 核心原则：高保真优先于文采

- **绝不删减实质信息**：不得省略前提条件、数字指标、时间约束、保留意见、否定词或语气中的犹豫/不确定信号（如“可能赶不上”“我个人不太建议”必须保留语义）。
- **绝不脑补缺失内容**：遇到 ASR 严重错乱、听不清或上下文无法 100% 确信的片段，保留原始片段并用行内标记提示：
  - 示例：`这块我们需要和 [ASR存疑: 齐总/企综] 再确认一下预算。`
- **不改写立场与情绪强度**：不要把“强烈反对”柔和成“略有保留”，也不要把“可以试试”夸大成“已经拍板”。

## 2. 清洗与校对细则

### 2.1 去除口语噪声与字幕碎片
- 删除无语义填充词与重复打结：如“嗯、啊、呃、那个那个、就是说、然后然后、对对对（作为纯附和且无新信息时）”。
- 保留**有表态意义的简短回应**：如在关键决策后的明确表态（“行，那我来跟进”“同意，就按方案二走”）必须保留，不能误删为口癖。
- 合并同一发言人被 ASR 切碎的连续短句，补全自然的中文/英文标点。

### 2.2 ASR 常见误识校对
结合会议主题、上下文与行业常识，修正明显同音错别字与中英混排误识：
- 同音/近音词：如 `排期 -> 排起`、`灰度 -> 灰渡`、`回归测试 -> 会规测试`、`埋点 -> 买点`。
- 常见英文缩写/技术词大小写统一：如 `API`、`PRD`、`QPS`、`SLA`、`OKR`、`ROI`、`UI/UX`。
- 人名/项目名：全稿保持完全一致的写法；若无法确定同音人名，优先采用原稿写法并在顶部“校对说明”中提示。

### 2.3 分段与时间戳策略
- **话题章节划分**：按逻辑话题或讨论阶段用 `##` 二级标题分隔（如 `## 01. Q3 指标复盘 [00:00:00 - 00:14:20]`），标题应尽量与 `<prefix>-讨论摘要.md` 呼应。
- **发言人分段**：每次切换发言人另起一段；同一发言人连续长段超过约 250~350 字时，在逻辑转折点适当拆段，提升阅读体验。
- **时间戳保留**：
  - 每次发言人切换的段首保留起始时间戳，格式统一为 `[MM:SS]`（不足 1 小时）或 `[HH:MM:SS]`（超过 1 小时，全稿统一位数）。
  - 同一人超长发言拆分为多段时，在新段首尽量保留对应时间戳。
  - 若原始文本本身完全不含时间戳，则不伪造时间戳，并在顶部“校对说明”注明“原始文稿不含时间戳”。

### 2.4 发言人映射表
当原始转写使用匿名标签（如 `发言人 1`、`Speaker 0`、`说话人 A`）时，在 `<prefix>-文字记录.md` 顶部提供映射表：

```markdown
## 发言人映射与校对说明

| 原文标识 | 推断/确认身份 | 推断依据 |
| :--- | :--- | :--- |
| 发言人 1 | 张三（产品经理） | `[00:01:12]` 自我介绍并主导需求讲解 |
| 发言人 2 | 待确认（疑似后端负责人） | `[00:15:40]` 提及负责接口排期，未出现姓名 |

- **校对说明**：已去除口语填充词并合并碎句；全稿共修正 X 处明显 ASR 误识，另有 Y 处语义存疑已用 `[ASR存疑: ...]` 标出。
```

## 3. `<prefix>-文字记录.md` 文档格式

```markdown
---
title: "<会议主题> - 清洗后文字记录"
date: "<YYYY-MM-DD>"
source_file: "<原始文件名>"
---

# <会议主题> - 清洗后文字记录

> **关联文档**：[会议纪要](./<prefix>-会议纪要.md) | [讨论摘要](./<prefix>-讨论摘要.md)

## 发言人映射与校对说明
<如无匿名发言人，可仅保留简短校对说明与参会人列表。>

---

## 01. <章节/议题标题> `[00:00:00 - 00:12:30]`

**张三** `[00:00:05]`：今天我们主要对齐一下下个版本的上线范围，先请李四同步一下目前的研发进度。

**李四** `[00:00:18]`：好的。核心链路昨天已经联调完成，但支付回调这块压测时发现一个并发锁的问题，预计还需要两天修复。

**张三** `[00:01:02]`：那这样看周四提测会有点紧，测试这边能不能先并行介入前半段？

---

## 02. <下一章节标题> `[00:12:30 - 00:28:45]`
...
```
